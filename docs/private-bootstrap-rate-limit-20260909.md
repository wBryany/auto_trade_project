# 私有连接初始化失败与限频恢复：2026-09-09

## 原因与影响

main / 8787 在北京时间 21:04:46 报 `'NoneType' object has no attribute 'sock'`。根因链条为：行情及账户连接短暂中断 → 重连时账户 REST 快照返回 HTTP 418 → 初始化回调主动调用 `WebSocketApp.close()` 清空 socket → websocket-client 在回调返回后仍访问 `app.sock.sock`，产生二次异常，覆盖真实的限频错误。

本机部署依赖为 websocket-client 1.9.1；测试环境为 1.9.2。两者都有上述回调/dispatcher 顺序，[官方客户端源码](https://websocket-client.readthedocs.io/en/latest/_modules/websocket/_app.html)也能核对该行为。本次修正调用方式，不升级或修改第三方安装包。

其他跳过对账的周期仍有 signal，最大相邻 signal 间隔 5.068 秒；不能把整个恢复窗口描述成持续停止本地管理。窗口内未发现下单失败或服务重启记录，首次现场核对为空仓。

成功 HTTP 权重日志采用跨分钟或增加 100 的采样，不能作为请求总次数。断线后首个已记录响应的共享 IP 权重已为 927；无法从这些日志证明具体哪些流量触发了出口封禁。本机另一 model2 服务日志使用 OKX，未发现它调用 Binance 的证据。本次修复不保证共享出口以后不会再次限频。

## 修复

初始化失败时仅停止客户端循环，保留 socket 直到 SDK 自己完成 teardown，避免提前清空。未恢复的初始化根因不会再被收尾阶段的普通 socket 错误覆盖。

私有快照读取保留原始 ApiError 的 HTTP 状态、交易所错误码及重试截止，每个调用者得到独立异常对象，避免重复使用跨线程异常与通知标志。未完成新快照时仍拒绝读取旧账户状态，认证失效及停止过程中不发布缓存为就绪。

重连及 listenKey 续期遵守已知限频截止；等待可被停止事件打断。网络级指数退避、订单保护、交易规则及已关闭的时间退出保持原逻辑。告警能够归类为 IP 限频，并展示可重试时间；处理建议改为等待后自动重试，不再要求每次短暂限频都切换节点和重启。

## 验证

真实 `WebSocketApp.run_forever` 配合内存模拟的底层传输，在旧 HEAD 上对 HTTP 418/429/500 的三例均复现相同 socket 二次异常；修复后三例均正确清理，保留真实错误。其他回归覆盖限频截止前不重连、不续期，停止可打断长等待，恢复后加载新快照，以及失效认证不能读取旧缓存。

另通过真实 adapter → engine → dashboard/CLI → 通知队列验证：保留 HTTP 418、-1003 与重试时间，采用既有有界等待，通知不再显示 socket 错误，且账户不可用时不提交订单。测试全部使用模拟传输和内存邮件发送函数，不接触真实交易或邮箱。生产版本 websocket-client 1.9.1 下的 11 项针对性测试也已通过。
