## 重复告警原因与修复

对账失败时，原有逻辑提前记录尝试时间，防止下一秒再次请求账户；这个节流是必要的。但 dashboard 和命令行循环把下一次未抛异常的行情周期一律视作恢复，即使这一轮因节流根本没有再次对账。`resolve_emergency` 清除了通知去重/冷却状态，dashboard 同时清除了可见错误及日志去重状态。于是同一连续故障产生三封紧急邮件和三条操作错误。

新增待恢复的对账错误状态：实际对账异常时设置并原样抛出；节流跳过时保留；只有完整对账成功才清除。dashboard 和命令行循环据此判断是否恢复 cycle 告警。dashboard 在未确认恢复时继续显示错误，仍更新成功周期的行情结果与时间。

变更不增加 REST 或 WebSocket 请求，不更改重连退避、5 秒对账间隔、通知冷却期限、策略或订单保护。普通周期异常在下一次成功周期仍正常恢复；对账恢复后新发生的故障仍可发出新告警。此次修复解决错误的恢复判断，不保证外部连接不再中断。
