## 修改

- 所有主服务 USD-M REST 请求共用进程级主动预算。读取成功与失败
  响应的实际 IP 权重，在普通工作达到额度的 75% 前暂停（默认
  1800/2400），并限制普通请求每个滚动 60 秒最多 60 次。
  exchangeInfo 若返回更低额度，则相应降低预算。
- 每次实际发往网络的尝试均计数和记录，包括重试及网络失败；日志只
  记录方法、主机、路径，不包含请求参数、签名、密钥或请求体。
  `/api/status` 的 `rest_requests` 区分本进程请求数、观察到的 IP
  权重及保守预留权重。它不声称统计代理出口上其他用户的流量。
- 预算保留最近 60 秒本地请求成本和服务器权重高水位，允许少量保守
  重复计数，避免乱序响应及跨分钟时丢失并发预留。使用服务器 Date
  与单调时钟定位窗口；无 Date 时保留已知时钟锚，首个有效 Date 可以
  纠正初始本地时间估计。
- 减仓、保护单、撤单和成交核对可使用预留额度。官方权重为零的保护/
  减仓 POST 不被本地 IP 预算拦截；真实 HTTP 418/429 等交易所限制仍
  优先阻挡全部请求。不会自动重放结果未知的下单请求。
- 本地暂停以 `LOCAL_REQUEST_BUDGET` 和明确截止时间传递，不在 HTTP
  层等待，避免签名过期或持有引擎锁长时间睡眠。空仓常规等待不冒充
  “IP 封禁”；真实拒绝、有仓异常、保护单/减仓/成交对账问题仍告警。
- 健康启动快照能明确证明保证金模式与杠杆已匹配时，不再重复 POST
  设置；字段缺失或冲突仍执行原配置确认，持仓保护恢复规则不变。
- 页面重启保留已知限频截止。终端部署对明确的本地等待或短暂 429
  最多重试两次，总预算 90 秒；等待在服务锁外，每次重新验证停止
  状态、健康账户、原仓位和保护单。418、未知错误、超时不自动重试。
